# qianjin-resume-rewriter · 简历改写专家

把**"职责罗列式"简历**改写成**"项目叙事式"简历**的 WorkBuddy 技能——让招聘方一眼看到你「在 XX 业务背景下，围绕 XX 核心目标，通过 XX 落地动作，解决 XX 业务痛点，达成 XX 量化成果」。

> 曾用名 `resume-project-narrative` / `qianjin-resume-narrative`，现定名 **`qianjin-resume-rewriter`**（`-er` 结尾 = 改写专家，与 `qianjin-content-repurposer` 同构词，均为 ZOORO-NEW 下 `qianjin-` 前缀家族成员）。

## 双引擎架构（v2.0）

简历只是武器库的 1/6，真正决定成败的是六件套协同。

- **引擎 A · 六步法改写**：明确目标 → 筛选经历 → 包装经历 → 对齐 JD → 量化成果 → 格式优化（基础，默认执行）
- **引擎 B · 求职武器库**（v2.0 新增）：简历多线版（顾问/VP/通用三定位）/ Cover Letter / 30 秒自我介绍 / VP 面试 10 题题库 / 30 分钟项目案例 / docx 排版落地

适用资深（10+ 年）求职者的还有 `references/senior-strategy.md`：姿态管理、薪资谈判、反向提问、复合背景差异化。

## 四条红线（v2.1.0 新增，优先级高于写作技巧）

v2.0 能力面大幅扩张，但实测（A/B 对照实验 + 双盲评审）发现改写质量出现**系统性纪律退化**。v2.1 补四条硬约束，每条带正反例：

| 红线 | 规则 | 修的是什么 |
|---|---|---|
| **A 推断标注纪律** | 背景句凡素材无出处，一律标`（推断，待核对）` | 推断标注从 7 处掉到 0 处 |
| **B 动词守恒** | 素材动词强度是上限，「参与」不得写主导/牵头/统筹 | 擅自升格 + 同段自相矛盾 |
| **C 资质不可挪移** | 不得为命中 JD 改变雇主性质定性 | 凭空把合作方说成品牌方 |
| **D 不加料** | 不得添加素材没有的时间限定词、机制名、职称 | 擅加"年"字造出自相矛盾 |

**为什么重要**：简历上写"主导"、面试答"我主要配合"——当场拆穿，比老老实实写"参与"丢分严重得多。

**改进效果（同一素材复跑实测）**：

| 检查项 | v1.1.1 | v2.0.0 | v2.1.0 |
|---|---|---|---|
| 推断标注数 | 7 | 0 | 6 |
| 动词违规次数（严格判） | 0 | 6 | **0** |
| 凭空定性雇主 | 0 | 2 | 0 |
| 擅加年限限定 | 4 | 8 | 2 |
| 算式留痕 | 0 | 0 | 9 |

## 为什么需要它

HR 筛一份简历平均 **6 秒**。"负责 XX、参与 XX"式职责清单只回答了"你做过什么"，而项目叙事式回答的是**"你解决了什么问题、创造了多少价值"**。

典型触发场景：HR 反馈「看不到解决问题的能力」「只有职责没有成果」。

## 三段式结构

```
项目背景（业务痛点 + 核心目标）
        ↓
项目职责（加粗能力块 + 落地动作 + 量化微成果）
        ↓
项目成果（最硬的 2-3 个数字 + 沉淀的可复用资产）
```

**改写前**

> 负责项目整体运营体系建设与管理，确定各渠道业务目标及业务流程，实现降本增效。

**改写后**

> **项目背景**：多品牌线定位重叠、传播口径不一，渠道结构单一；核心目标是梳理品牌矩阵、重构运营模式。
> **运营模式重构**：重构以私人诊所为基、医院为背书、大健康跨界为补充的"三位一体"运营体系，打通专业背书与消费端传播链路，实现降本增效。

## 能解决什么

| 场景 | 处理方式 |
|------|---------|
| HR 说"看不到解决问题的能力" | 全篇改造为项目三段式叙事 |
| 短期经历太多（如"5 年内 ≤2 段"） | 同业合并为一个条目，内部拆「项目一/项目二」，数字各归各主 |
| 数字太干、体现不了价值 | 价值量化五锚点：钱 / 增长 / 效率 / 规模 / 获客转化 |
| 数字自相矛盾（如"A→B 提升 X%，又写提升 Y%"） | 数据一致性体检清单 |
| 按 JD 定制 | 用 JD 原话重写能力块标题与成果描述 |
| 一份简历想打多个岗位 | 多线定位：顾问销售型 / VP 战略型 / 通用求职型三套，姿态不混用 |
| 简历之外还要准备什么 | Cover Letter + 30 秒自我介绍 + 面试题库 + 项目案例（六件套） |

## 安装

```bash
git clone https://github.com/ZOORO-NEW/qianjin-resume-rewriter.git ~/.workbuddy/skills/qianjin-resume-rewriter
```

重启 WorkBuddy 后，在对话中直接说需求即可，例如：

- 「按项目叙事改写这份简历」
- 「HR 说我简历看不到解决问题的能力，帮我重做」
- 「这几段短期经历怎么合并才不显得跳槽频繁」
- 「怎么量化体现我为公司创造的价值」
- 「我要投 VP，帮我做定位 B 版本 + Cover Letter + 面试题库」
- 「这份简历排版美化一下，要能直接投递」

## 红线

-严禁编造公司、职位、数字；量化只能基于用户素材合理推演。
- 项目背景若为合理推断，交付时必须提示用户核对（面试必被追问）。
- 数字一致性：同一指标换算后的倍数不能自相矛盾。
- **动词守恒**：「参与/协助」不得升格为「主导/牵头/统筹」；做足做法细节，而不是拔高头衔。
- **资质不可挪移**：不得为命中 JD 把合作方/服务商说成品牌方。
- 永不覆盖用户原始简历文件，新版本另存。
