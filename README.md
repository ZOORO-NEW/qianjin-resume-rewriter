# qianjin-resume-rewriter

把**"职责罗列式"简历**改写成**"项目叙事式"简历**的 WorkBuddy 技能——让招聘方一眼看到你「在 XX 业务背景下，围绕 XX 核心目标，通过 XX 落地动作，解决 XX 业务痛点，达成 XX 量化成果」。

> 曾用名 `resume-project-narrative` / `qianjin-resume-narrative`，现定名 **`qianjin-resume-rewriter`**（`-er` 结尾 = 改写专家，与 `qianjin-content-repurposer` 同构词，均为 ZOORO-NEW 下 `qianjin-` 前缀家族成员）。

## 为什么需要它

HR 筛一份简历平均 **6 秒**。"负责 XX、参与 XX"式职责清单只回答了"你做过什么"，而项目叙事式回答的是**"你解决了什么问题、创造了多少价值"**。

典型触发场景：HR 反馈「看不到解决问题的能力」「只有职责没有成果」。

## 三段式结构

```
项目背景（业务痛点 + 核心目标）
        ↓
项目职责（加粗能力块 + 落地动作 + 量化微成果）
        ↓
项目成果（最硬的 2-3 个数字 + 沉淀的可复用资产）
```

**改写前**

> 负责项目整体运营体系建设与管理，确定各渠道业务目标及业务流程，实现降本增效。

**改写后**

> **项目背景**：多品牌线定位重叠、传播口径不一，渠道结构单一；核心目标是梳理品牌矩阵、重构运营模式。
> **运营模式重构**：重构以私人诊所为基、医院为背书、大健康跨界为补充的"三位一体"运营体系，打通专业背书与消费端传播链路，实现降本增效。

## 能解决什么

| 场景 | 处理方式 |
|------|---------|
| HR 说"看不到解决问题的能力" | 全篇改造为项目三段式叙事 |
| 短期经历太多（如"5 年内 ≤2 段"） | 同业合并为一个条目，内部拆「项目一/项目二」，数字各归各主 |
| 数字太干、体现不了价值 | 价值量化五锚点：钱 / 增长 / 效率 / 规模 / 获客转化 |
| 数字自相矛盾（如"20 万→400 万，提升 50%"） | 数据一致性体检清单 |
| 按 JD 定制 | 用 JD 原话重写能力块标题与成果描述 |

## 安装

```bash
git clone https://github.com/ZOORO-NEW/qianjin-resume-rewriter.git ~/.workbuddy/skills/qianjin-resume-rewriter
```

重启 WorkBuddy 后，在对话中直接说需求即可，例如：

- 「按项目叙事改写这份简历」
- 「HR 说我简历看不到解决问题的能力，帮我重做」
- 「这几段短期经历怎么合并才不显得跳槽频繁」
- 「怎么量化体现我为公司创造的价值」

## 内置工具

```bash
# 离线提取 docx 纯文本（零依赖，用于读取原简历）
python scripts/extract_docx_text.py 你的简历.docx
```

## 文件结构

- `SKILL.md` —— 触发条件、核心格式、8 步改写工作流、质量自检清单
- `references/format-guide.md` —— 完整模板 + 价值量化五锚点 + 能力块命名库 + 真实 Before→After 案例 + docx 交付命令与路径坑
- `scripts/extract_docx_text.py` —— docx → 纯文本离线提取（零依赖）

## 红线

- 严禁编造公司、职位、数字；量化只能基于用户素材合理推演。
- 项目背景若为合理推断，交付时必须提示用户核对（面试必被追问）。
- 永不覆盖用户原始简历文件，新版本另存。
