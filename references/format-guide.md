# 项目叙事式简历——格式与量化完全指南

## 一、为什么这个格式有效

招聘官筛简历平均 6 秒。"负责 XX"式职责清单只回答了"你做过什么"，而项目叙事式回答的是"你解决了什么问题、创造了多少价值"。三段式对应招聘方的完整判断链：

- **项目背景**（为什么要做）→ 判断业务理解力
- **项目职责**（具体怎么做）→ 判断方法论与执行力
- **项目成果**（做成了什么）→ 判断结果导向

## 二、完整模板

```markdown
### [起止时间]  [职位名称] | [所属行业]
*[公司A]（[时间段]）· [业务线] ｜ [公司B]（[时间段]）· [业务线]*

**项目一：[项目名称]（公司A）**

- **项目背景**：[赛道/业务] 同质化竞争激烈，公司"[核心痛点]"，缺乏[差异化能力]与系统化[目标体系]；
  核心目标是从 [起点] 建立 [核心资产]，跑通"[关键环节—关键环节—关键环节]"闭环。
- **项目职责**：
  - **[能力块标题1]**：拆解[行业格局/用户决策链路]，0-1 搭建[体系]（[具体交付物]），
    确立差异化定位，推动 [核心指标] 达到 [目标水平]。
  - **[能力块标题2]**：以[核心目标]为中心，统筹[活动/渠道/团队]，
    建立 [合作方类型] 合作关系。
  - **[能力块标题3]**：搭建"[渠道1 + 渠道2 + 渠道3]"内容矩阵，
    栏目化种草引流私域，[核心指标] 由 [起点] 增至 [终点]（约 [N] 倍）。
  - **[能力块标题4]**：基于 [模型] 搭建用户 [LTV/分层] 运营体系，优化内容与资源分配。
- **项目成果**：[核心指标] 年增长 [N] 倍，[品牌/排名] 跻身行业 [水平]；沉淀可复制的 [模型/方法论]。
```

### 填充时的两条硬约束（v2.1.0 新增）

模板里的方括号是**给你填的**，不是让你编的：

**1. 推断必标注**
模板里的「赛道同质化竞争激烈」「缺乏内容化能力」这类背景句，凡用户素材里没有直接依据的，句末必须加 `（推断，待核对）`。
-✅ `**项目背景**：美妆赛道同质化竞争激烈，公司"有产品、无品牌"（推断，待核对）；核心目标是……`
- ❌ `**项目背景**：品牌方自营渠道增长乏力，策略分散、定价与库存缺乏统一视角。`（素材没这句 = 凭空生成且未标注）

**2. 动词守恒**
模板写「统筹[活动/渠道/团队]」，**只有素材原文就是"统筹/主导"才能用**；素材是"参与"就写参与。
- ❌ 素材「参与选品谈判」→ `主导选品谈判`
- ✅ `参与选品谈判，对接过3 类供应商，比较账期与起订量，输出选品准入建议`

**3. 不加限定词**
模板里的 `[N]倍` 前不要自行加"年/季度/月"。素材写「GMV 300万→2000万」就写"GMV 由 300 万增至 2000 万"，加了"年"可能与素材里其他数字撞出矛盾。

## 二·五、一个真实完整示例（示范数字粒度与诚实标注）

> 演示：同样的素材，用占位符能填，但**真实数字才有说服力**——所以示范时用真数字（面试时用户会替换成自己的）。

### 2022.6 – 2025.7　品牌与整合营销总监 | 医疗器械领域
*以 A 公司（2022.6–2024.4）为主｜ B 公司（2024.6–2025.7）*

**项目一：品牌 0-1 建设与全域增长（A 公司）**

- **项目背景**：赛道同质化竞争激烈，公司"有产品、无品牌"，缺乏差异化认知与系统化线上获客体系（推断，待核对）；核心目标是从 0 建立品牌资产，跑通"种草—获客—转化"增长闭环。
- **项目职责**：
  - **业务诊断与品牌定位**：拆解行业格局与用户决策链路，0-1 搭建品牌体系（Logo / VI / 知识产权），确立差异化定位，推动品牌跻身行业前三。
  - **整合营销与全域获客**：以招商转化为核心目标，统筹招商会 / 展会 / 直播招商会，建立媒体、专家与渠道合作关系。
  - **新媒体矩阵与转化闭环**：搭建"公众号 + 知乎 + 小红书 + 抖音"内容矩阵，栏目化种草引流私域，小程序月 GMV 由 20 万增至 400 万+（约 20 倍）。
  - **数据驱动增长**：基于 AARRR 模型搭建用户 LTV 运营体系，优化内容与资源分配。
- **项目成果**：产品 GMV 年增长 5 倍，品牌跻身行业前三；沉淀可复制的增长模型。

**对比：同一段素材的错误写法**

| 错误类型 |❌ 错误示例 | 问题 |
|---|---|---|
| 动词拔高 | `主导品牌体系搭建与年度生意规划` | 素材只有"负责品牌体系搭建" → 违反红线B |
| 资质挪移 | `具备品牌方 + MCN 双视角` | 把"对接品牌方合作"说成自己是品牌方 → 违反红线 C |
| 擅加限定词 | `品牌年 GMV 由 300 万增至 2000 万` | 加"年"可能与大促单期数字撞出矛盾 → 违反红线 D |
| 推断未标 | `渠道策略分散、缺乏统一生意视角` | 素材没这句，纯生成 → 违反红线 A |
| 倍数含混 | `增长约 6.7 倍` | 未说明是"达到6.7倍"还是"增长6.7倍"，后者解读即错 |

## 三、价值量化五锚点（优先用钱，其次增长）

| 锚点 | 公司关心的"那笔账" | 示例写法 |
|---|---|---|
| 💰 钱 | 营收 / GMV / 利润 / 节省成本 / 管理预算 | 年销 [规模]；人力成本降 [X]%（年省约 XX 万） |
| 📈 增长 | 增长率、X→Y、市场份额 | GMV 年增 [N] 倍；获客月增 [X]% |
| ⚡ 效率 | 时间 / 人力 / 单产提升 | 内容产能提升 [N] 倍；上线周期缩短 [X]% |
| 🌐 规模 | 用户 / 门店 / 渠道 / 触达 | 覆盖 [N] 家门店；沉淀 [N] 用户 |
| 🎯 获客转化 | 线索量、CAC、转化率、私域沉淀 | 精准获客月增 [X]%；下单转化率提升 [X]% |

**核心公式：强动词 + 动作 + 量化结果 + 业务影响**

- ❌ 弱：负责品牌体系搭建与宣传。
- ✅ 强：0-1 搭建品牌体系（VI/知识产权），带动品牌辨识度 +[X]%、产品线 GMV 年增 [N] 倍。

**隐形价值也要量化**（容易被忽略）：
- 合规/风险：清除搜索负面信息 → 挽回品牌信任资产、降低合规与客诉风险
- 组织资产：沉淀 X 套可复用 SOP，新人上手周期缩短 XX%
- 赋能：培训 X 家代理商/门店，平均单店产出提升 XX%

## 四、能力块命名库（按岗位选用 3-4 个）

- 通用：业务诊断与策略制定 / 数据驱动增长 / 团队搭建与协同 / 跨部门项目落地
- 营销/运营：品牌定位与信任修复 / 整合营销与全域获客 / 新媒体矩阵与转化闭环 / 内容电商运营 / 私域运营与裂变 / KA 品牌事件营销 / AI 赋能与组织提效
- 产品/设计：用户研究与需求洞察 / 界面设计与创新 / 交互优化与转化提升 / 设计规范与组件沉淀
- 技术：架构设计与重构 / 性能优化 / 稳定性保障 / 工程效能提升

## 五、数据一致性检查清单

1. 同一指标的不同表述不能矛盾（如"A→B"换算后的倍数要与所有相关表述一致，不能一处说"翻 N 倍"、另一处说"提升 M%"且 N 与 M 不匹配）。
2. 百分比要有基准（环比/同比/期间累计），口径不清用"约/近"。
3. 合并经历时，数字必须归属于真实发生的公司，禁止把 A 的战绩写进 B 的项目。
4. 所有数字必须经得起面试追问；估算值建议用户标注口径。

## 六、真实 Before→After 案例（营销总监岗）

**Before（职责清单式）**
> 负责项目的整体运营体系建设与管理，确定各渠道的业务目标及业务流程，实现降本增效。

**After（项目叙事式）**
> **项目背景**：多品牌线定位重叠、传播口径不一，渠道结构单一；核心目标是梳理品牌矩阵、重构运营模式。
> **运营模式重构**：重构以私人诊所为基、医院为背书、大健康跨界为补充的"三位一体"运营体系，打通专业背书与消费端传播链路，实现降本增效。

## 七、明确目标与 JD 拆解（优化的起点）

没有目标的简历优化是无效优化。动手前先锁定"打谁"：

1. **锁定目标**：目标岗位 + 行业 + 意向公司/层级（如"互联网大厂 高级运营"）。
2. **拆解 JD**（若有）：
   - 硬性要求：年限、学历、硬技能、行业经验。
   - 软性要求：能力特质（如"数据驱动""从 0 到 1"）。
   - 高频关键词：原样提取，后续自然融入简历（ATS + 人读双过关）。
3. **推导能力优先级**（若无 JD）：基于目标岗位共性，列招聘方最关心的 3-4 条能力线，作为改写主线。
4. **输出目标画像**：一句话概括"这份简历要证明我能胜任 XX 岗的 XX 能力"，后续每段经历都回扣它。

## 八、经历筛选标准（做减法）

从全量经历中按目标画像取舍：

| 类型 | 判断 | 处理 |
|---|---|---|
| 强相关 + 有硬数字 | 直接命中 JD 能力线 | 重点展开、前置 |
| 弱相关 + 可迁移能力 | 能力可平移 | 保留但精简 |
| 无关 / 超过 10 年 | 与目标无关 | 一笔带过或删除 |
| 战绩最硬 | 数字最亮眼 | 排前、"以 X 为主" |

合并：近 5 年主条目 ≤2 段；同业短经历合并为一条（标题写领域，副行标真实公司+时间段），内部拆「项目一/项目二」各完整叙事。

## 九、JD 与结果对齐表（让经历长在点上）

把 JD 要求逐条对应到简历呈现，避免"写了很多却没打中"：

| JD 关注的能力 | 落到简历的哪里 | 呈现要点 |
|---|---|---|
| 增长 / 获客 | 项目成果 + 能力块标题 | 突出 GMV / 获客 / 转化率数字 |
| 效率 / 降本 | 项目职责 + 成果 | 突出周期缩短 / 成本下降 % |
| 0-1 搭建 | 项目背景 + 职责 | 强调"从 0 建立体系" |
| 团队 / 管理 | 能力块 | 带人数 / 架构 / 协同结果 |
| 数据驱动 | 职责描述 | 嵌入 AARRR / 漏斗 / 看板等词 |

同一能力跨多项目时，用递进写法（0-1 → 规模化 → 体系化）体现成长，而非重复罗列。

## 十、ATS 与格式优化清单

- **ATS 友好**：避免图片 / 表格 / 文本框 / 复杂分栏；关键词与 JD 同义表述，便于机器解析。
- **可扫读**：每段 3-4 个加粗能力块小标题；一屏可见"痛点 + 成果"。
- **分层呈现**：个人信息 → 摘要 / 核心能力 → 经历（重点前置）→ 教育 / 其他。
- **一致性**：数字口径统一；时间线连续；公司名 / 职位名前后一致。
- **克制**：一页（junior）/ 两页（senior）为上限；不写离职原因、不写自我评价空话。

## 十一、docx 交付流程（tencent-local-office-edit）

```bash
# 1. 定位 edsdk.py（注意：路径随 WorkBuddy 版本变化，先找再用）
#    2026-09 起位于插件缓存目录，按版本号选最新：
ls "C:/Users/$USER/.workbuddy/plugins/cache/workbuddy-builtin/" | grep local-office
#    旧路径 resources/app.asar.unpacked/.../builtin-skills/ 已废弃

# 2. 三步生成（cd 到 edsdk.py 所在目录执行）
python edsdk.py call create_doc
python edsdk.py call doc_insert_markdown file_id=<id> idx=0 markdown="file://<md绝对路径>"
python edsdk.py call save_file file_id=<id> file_path="<目标docx绝对路径>"
```

**坑位备忘**：
- `open_file` 打开已有文档后读取可能报 "document is not open"（打开态与内核不一致）——改用 `create_doc` 新建实例写入最稳。
- markdown 内容用 `file://` 传路径，避免长字符串转义问题。
- 生成后用 `scripts/extract_docx_text.py` 回读校验内容完整性。
- **永远不要覆盖用户原始简历文件**，新版本另存（命名规则：`原名-版本特性.docx`，如 `我的简历-项目叙事版.docx`）。
